An activation tensor is useful only with its provenance

This February 2026 infrastructure report explains harvesting activations from Kimi K2 Thinking at trillion-parameter scale. The scientific objective is an SAE training dataset; the engineering problem is extracting billions of token representations without stalling optimized inference or losing their connection to the original text. The main lesson is that data movement, scheduling semantics, and metadata correctness are part of experimental validity.

Prerequisites: tensor dimensions, systems measurement, and SAE fundamentals. Prefill processes known input tokens in parallel subject to causal masking. Decode samples new tokens autoregressively. Tensor parallelism partitions model computation across devices. A capture record must identify the logical sequence, absolute token offset, layer, and capture mode, even when the serving engine flattens or splits physical batches.

Original teaching calculation: throughput and storage must agree

Let $T$ be token count, $d$ activation width, and $b$ stored bytes per entry. Uncompressed activation storage is $S=Tdb$. With invented dimensions $T=3\times10^9$, $d=6144$, and $b=2$, this is $36.864\times10^{12}$ bytes, or 36.864 decimal TB. The source's approximately 33 TB compressed figure is a separate reported measurement; this calculation does not infer its exact dtype, width, or compression ratio.

At capture rate $r$ tokens per second, raw data arrive at $rdb$ bytes per second. If the writer sustains $w$ bytes per second with $w\lt rdb$, backlog grows at rate $rdb-w$. A finite buffer of size $B$ fills after approximately $B/(rdb-w)$ seconds. Asynchronous I/O hides temporary delays; it cannot fix a permanent throughput deficit.

For an invented case, an arrival rate of 200 MB/s, writer rate 150 MB/s, and 10 GB buffer exhaust capacity in roughly 200 seconds using decimal units. The system must then apply backpressure, reduce capture rate, or explicitly drop data. Silent dropping changes the training distribution and may preferentially exclude long or difficult requests.

The report gives 14,000 tokens per second on an eight-GPU node and ten concurrent nodes for a six-hour job. A direct arithmetic check is $3\times10^9/(10\cdot14000)\approx21429$ seconds, or 5.95 hours. This verifies the reported scale relationship, not actual local performance or linear scaling on arbitrary hardware.

Three stages, several correctness invariants

“Shipping activations off the GPU” describes device-side staging, a sidecar transfer thread using pinned CPU memory, and a writer reconstructing per-sequence records. A readiness event prevents reading a buffer before a copy completes. A buffer must also remain owned until all consumers finish; otherwise reuse can silently substitute later activations for earlier metadata.

“Metadata: putting the pieces together” explains why continuous batching and chunked prefill complicate provenance. A physical tensor can contain unrelated logical sequences. The writer must split it using lengths and offsets, then compose chunk offsets into absolute positions. Mode-dependent metadata fields cannot be interpreted identically in prefill and decode.

Capturing at a tensor-parallel synchronization point avoids partial representations or duplicated captures across ranks. The report deliberately excludes CUDA-graph support because its immediate workload is prefill. This is a scoped engineering choice, not a claim that all interpretability workloads can ignore decode. Real-time monitoring and steering introduce different requirements.

Speed is necessary, integrity is decisive

“Results: What we built” reports the billion-token harvesting run and subsequent SAE/steering demonstrations. The infrastructure report does not provide a complete scientific validation of every interpreted feature. Likewise, a high throughput benchmark does not establish that every activation is correctly labeled. These need separate evidence.

A strong validation compares captured tensors against a slow reference forward pass on small deterministic sequences, including chunk boundaries, repeated prefixes, concurrent requests, and different batch orders. Check that each expected token appears exactly once and that tokens never cross sequence identities. Numerical agreement tolerances must account for precision and runtime differences without concealing indexing mistakes.

The report's contrast between compute-bound prefill and bandwidth-bound decode describes a common operating regime. Actual bottlenecks depend on model, batch size, hardware, attention implementation, and context length. Capacity planning should measure each stage instead of assuming that faster model kernels automatically improve end-to-end collection.

Reading route and capability

Read “Inference server optimizations,” “Prefill vs. Decode,” “Controlling complexity,” “Shipping activations off the GPU,” and “Metadata.” You should trace one token from logical document to stored vector and identify every boundary where identity, ordering, or ownership can fail. Compare live monitoring for the additional constraints of synchronous serving.

Exercises

  1. Why is a tensor with correct shape insufficient evidence of a valid activation dataset?
  2. How long does collecting one billion tokens take at 20,000 tokens per second? What raw storage is needed for width 4,096 at two bytes per entry?
  3. Design a provenance test for chunked, continuously batched prefill.
