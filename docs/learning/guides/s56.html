Which risks does an interpretability interface change?

The December 23, 2024 safety statement describes Goodfire's release approach: moderate exposed features, filter inputs and outputs, provide controlled research access, and collaborate on auditing. It is a policy description and commitment, not a quantitative demonstration that these measures prevent misuse. Its historical context is the Ember feature-steering interface. Optional preparation: how feature interventions work and evaluation under uncertainty.

Map each control to a failure channel

Feature moderation restricts which internal directions users can directly manipulate. Input filtering screens requests before generation. Output filtering screens generated text. Controlled access changes who may examine restricted features. Collaboration and red-teaming aim to discover gaps in those controls. These are different intervention points, so effectiveness should be measured separately as well as jointly.

Restricting an exposed feature does not delete the underlying model capability. Multiple directions can support the same behavior, and combinations of permitted features can have effects not apparent from individual labels. Input/output filters also have false positives and false negatives. A layered interface can reduce risk without providing a theorem about all possible interactions.

A simple risk decomposition

Let $H$ mean a harmful interaction, $A$ that a request passes input screening, and $B$ that the harmful output passes output screening. Define the unconditional harmful-output release rate $P(H\cap A\cap B)=P(H)P(A\mid H)P(B\mid H,A)$. This is the probability chain rule, so it needs no independence assumption. The last term must be measured on what survives the earlier stage.

Multiplying separate marginal miss rates, such as $P(A\mid H)P(B\mid H)$, assumes a relationship that may be false. Filters can share blind spots. Conversely, one filter may catch precisely the failures missed by another. Architecture diagrams alone cannot establish defense diversity.

Original numerical example: correlated safeguards

Suppose an invented test set has 100 harmful requests. The input filter misses ten. If the output filter misses half of those survivors, five harmful outputs escape and conditional combined recall is 95%. Testing the output filter on all 100 requests might show only 10% misses, tempting an incorrect estimate of one escape. That estimate fails because the ten input-filter misses are an unusually difficult subset.

A benign-traffic calculation matters too. If 10,000 benign requests have a 1% false-positive rate, 100 benign requests are blocked. A filter can therefore create more benign blocks than harmful catches in low-base-rate traffic. The appropriate tradeoff depends on context, severity, and user experience rather than one accuracy number.

What evidence is absent from a policy statement?

The source names categories removed from public access and describes researcher-request review. It supplies no benchmark size, attack distribution, recall, false-positive rate, or measured residual risk. Its language about robust moderation is an organizational claim. The scientifically correct reading is that these controls were described, while their actual effectiveness requires separate evidence.

Auditing should distinguish accidental misuse from adaptive attacks, individual feature interventions from combinations, and public access from approved research access. Strong evaluation also tests whether removing obvious labels merely shifts misuse toward less obvious directions. A successful red-team demonstration can expose one vulnerability without estimating its population frequency.

Interpretability tools are dual use: they can help characterize failure mechanisms and also make them easier to elicit. The statement acknowledges this by combining research collaboration with access restrictions. The key empirical question is the change in risk relative to the same base model without the interface, including the safety improvements enabled by better auditing. This cannot be decided solely from the existence of the tool or from a release policy.

A useful audit protocol would report attacks and benign tasks under a fixed threat model, evaluate controls in their actual order, separate discovery and confirmation sets, and record how failures change after remediation. It should also examine whether genuine safety researchers can obtain enough access to reproduce findings. Those are proposed evaluation criteria, not claims that the source already performed them.

Reading locators

Read “Advancing Safety Research,” the three parts of “Our Safety Measures,” and “Commitment to Research Collaboration.” Be able to identify each control's intervention point and explain why a policy commitment is not an effectiveness estimate. Local labs illustrate conditional probabilities and classifier tradeoffs.

Exercises

  1. Concept. Why does removing a harmful feature from a public API fail to establish that the model no longer has the corresponding capability?
  2. Math. If the input stage passes 20% of harmful requests and the output stage passes 15% of those survivors, what fraction escapes?
  3. Critique. Propose a test that distinguishes complementary safeguards from two safeguards with shared blind spots.
