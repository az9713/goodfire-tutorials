What does releasing an SAE actually enable?

The January 10, 2025 announcement releases sparse autoencoders for Llama 3.1 8B and Llama 3.3 70B. It is an artifact announcement with a few implementation and evaluation details, not a new comprehensive scientific comparison. The main benefit is reusable access to interpreter models rather than requiring every researcher to harvest activations and train an interpreter from scratch. Optional preparation: SAE construction and the 70B feature map.

An interpreter has a precise input contract

An SAE encoder $E:\mathbb R^d\to\mathbb R^K$ is trained on the activation distribution of a specific model and hook site. Its decoder $D$ maps features back to that same activation space. The release targets layer 19 for the 8B model and layer 50 for the 70B model. Matching vector dimension alone is insufficient: a different layer, checkpoint, normalization convention, or tokenization pipeline can change the activation distribution and feature meaning.

The announcement builds on earlier Llama-3-8B work but names Llama 3.1 8B for this artifact. Those checkpoints should not be silently interchanged. A reproduction record needs exact model revision, hook location, SAE weights, dtype, normalization, and inference preprocessing. The historical API notebooks are optional context; the related research pages now record API deprecation in February 2026.

Read active counts without inventing density

For feature vector $z_i\in\mathbb R^K$, define $\|z_i\|_0$ as the count of nonzero coordinates. Average active count is $\bar L_0=N^{-1}\sum_{i=1}^N\|z_i\|_0$, where $N$ is the number of activation samples. The announcement reports counts 91 for the 8B SAE and 121 for the 70B SAE. These do not by themselves specify active fractions, because dictionary widths and evaluation distributions must also be known.

Reconstruction and active count are complementary but incomplete. A dictionary can reconstruct well while mixing concepts, or have clean labels while missing rare task-relevant information. The announcement also evaluates feature steering using Claude 3.5 Sonnet ratings of behavior, coherence, and relevance. Such ratings support the tested interface use case but do not establish precise causal semantics for every released feature.

Original worked comparison

For an invented dictionary with $K=16,384$ and average 91 active coordinates, active fraction is $91/16,384\approx0.00555$, or 0.555%. A second invented dictionary with $K=65,536$ and 121 active coordinates has fraction about 0.185%. The second has more active coordinates yet a lower active fraction. These widths are teaching assumptions, not specifications of the released artifacts.

Dense decoder storage scales as $dK$ numbers, even when only a few coefficients are active for an input. Sparsity of feature activations does not imply a tiny interpreter file or zero inference overhead. If decoder and encoder are both dense, one must account for their matrix operations as well as the base language model.

An artifact is a starting point for validation

Reusable interpreters permit feature inspection, steering experiments, and comparisons across research methods. They do not remove the need to test compatibility and domain coverage. A chat-trained SAE may underdescribe code, long reasoning traces, or a specialized scientific domain. Open weights also do not guarantee that old hosted feature labels or service endpoints remain available.

A sound first local check would run known compatible activations through the interpreter, measure reconstruction error and active-count distributions, inspect dead or extremely frequent features, and compare the base model's output with residual-preserving interventions. After those checks, evaluate a specific research question on held-out examples. Running a 70B model is outside a lightweight offline exercise; the release's accessibility should not be confused with low hardware requirements.

The adjective “state-of-the-art” is the announcement's dated characterization. The post gives no exhaustive benchmark establishing that rank for every possible SAE objective. Read its concrete artifact details and stated metrics rather than carrying a historical superlative forward as a current fact. The later practical guide is useful when deciding whether an SAE is needed at all.

Exercises

  1. Concept. Why can equal activation dimensions fail to make an SAE transferable?
  2. Math. If a dictionary doubles its width while average active count increases by 25%, how does active fraction change?
  3. Critique. Design a compatibility test before trusting feature labels on a new checkpoint.
