This companion uses those descriptions to organize questions and supplies an original causal toy example. It does not claim to have watched the recordings or reproduce arguments absent from the page.

Prerequisites: causal models, transformer concepts, and geometric representation models. A causal model specifies variables and how interventions change them. A computational motif is a recurring functional pattern, potentially implemented differently across networks. A model system is a simplified setting selected to make a phenomenon experimentally tractable. These definitions orient the listed topics; they are not attributed quotations from the lectures.

Original teaching example: correlation versus intervention

Let an input variable $X\in\{0,1\}$ determine hidden state $H=X$ and output $Y=X$. Observationally, $H=Y$ always. Yet intervening to set $H$ does not change $Y$, because the output equation uses $X$ directly. Compare a second model with $H=X$ and $Y=H$. It has the same observational relation but a different intervention response:

$$Y_{\operatorname{do}(H=0)}=X\quad\text{in model 1},\qquad Y_{\operatorname{do}(H=0)}=0\quad\text{in model 2}.$$

At input $X=1$, the intervention distinguishes the models. Thus perfect hidden-state prediction of an answer cannot alone identify its causal role. A proposed abstraction needs counterfactual tests that discriminate alternative computational stories. Real network interventions add challenges because arbitrary state replacements can leave the natural activation distribution.

The key distinction is between naming a phenomenon, identifying an implementation, and validating an explanatory model. A recurring motif can guide discovery but cannot substitute for checking that a particular network actually uses it. Likewise, a tractable model system can expose a principle while leaving its transfer to frontier models unproven.
