Source 39 · Research case study · June 11, 2025

Can circuit tracing rediscover a known comparison mechanism?

The source trains cross-layer transcoders on GPT-2 Small and investigates prompts such as a war lasting from an initial year to a later year. The task has a previously studied greater-than circuit, making it a useful test of whether a new microscope recovers known structure and where its decomposition differs.

Preparation: dot products and linear readouts, residual writes and logits, causal evidence, transcoders.

Feature discovery from one prompt, interpretation across many

The task asks for a two-digit completion greater than an initial two-digit year suffix. The source builds an attribution graph for one particular prompt with initial suffix 11, selects influential features from that graph, then sweeps initial suffixes to construct input-output attribution heatmaps. This is a deliberate asymmetry: feature discovery is local, while interpretation uses a larger prompt family.

A CLT feature at one layer can write to that layer and later MLP outputs. A full replacement substitutes reconstructions throughout the network. A local replacement adds the reconstruction error back to preserve original forward activations at the analyzed point. Error correction helps local analysis but does not mean the learned feature basis completely captures the original computation under all interventions.

What the attribution heatmap measures

Let feature $f$ at layer $\ell$ have activation $a_f^\ell$. Let $d_f^{\ell,i}\in\mathbb R^d$ be its decoder write into target layer $i$. The source sums writes into a residual-space vector

$$v_f^\ell=a_f^\ell\sum_{i=\ell}^{L}d_f^{\ell,i}.$$

For output token $t$ with unembedding vector $u_t$, direct logit attribution is $A(f,\ell,t)=u_t^\top v_f^\ell$. The dot product measures promotion or suppression in this linear readout. It is not the full finite intervention effect through all later nonlinear computation, normalization, and feedback paths.

For each initial suffix $y$ and possible completion $z$, a heatmap records $A_{y,z}$. A true general greater-than pattern would distinguish the relative order of $y$ and $z$, often producing a boundary near $z=y$. A feature that always favors large $z$ can help on some prompts without computing the comparison. This is why “promotes large numbers” and “implements greater-than” must not be treated as synonyms.

Original worked example: a useful but incorrect heuristic

Consider possible suffixes $0,1,2,3$ and a feature with constant decoder scores $b=(-2,-1,1,2)$, active with value one on every input. It favors large outputs. For initial suffix $y=1$, its positive scores favor valid completions 2 and 3. For $y=3$, its strongest preference is 3, which is not greater than 3. Its heatmap has repeated rows rather than a diagonal comparison boundary.

Now use feature activation $a(y)=\mathbf1_{y=1}$ with the same decoder. The heatmap is nonzero only on one input row. That feature can look task-specific and powerful on the discovery prompt while revealing little about the general algorithm. This is an original analytic example, not one of the source's learned features.

A third feature can encode parity: promote even outputs after odd inputs. Such a feature has interpretable numerical structure but does not enforce greater-than. Interpretability of a component and relevance to the intended task are independent questions.

Successes that expose methodological questions

The source finds large-number and comparison-related features, narrowly input-selective features, parity-related structure, and other structured-number features. Some resemble the prior neuron analysis, while others show weaker input dependence or resemble special-case lookups. Its discussion asks whether sparsity changes the apparent organization of number computation and recommends studying families of attribution graphs.

These findings support the tool's ability to surface interesting task-related hypotheses without manually designing every feature. They do not establish that the CLT's feature ontology is the original model's unique algorithm. Selection from one suffix privileges mechanisms active there; hand-selecting especially clear examples is useful for illustration but cannot estimate overall interpretability.

To strengthen the test, discover features on multiple suffixes, validate with held-out nouns and centuries, compare finite interventions with attribution predictions, and quantify reconstruction-error contributions. A known mechanism is a valuable benchmark, but agreement with a prior interpretation is itself evidence to assess rather than an unquestionable ground truth for every detail.

Exercises

  1. Conceptual: Why can an abstract parity feature be real yet unhelpful for greater-than?
  2. Mathematical: If $a=2$, decoder writes are $(1,0)$ and $(0,3)$, and unembedding is $(4,-1)$, compute summed direct logit attribution.
  3. Critical experiment: How would you test whether narrow features are fragments of a shared algorithm or independent lookup mechanisms?
